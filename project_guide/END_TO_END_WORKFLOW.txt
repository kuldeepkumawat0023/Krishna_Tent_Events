================================================================================
  KRISHNA TENT & EVENTS ERP - END-TO-END WORKFLOW & RESTful API SPECIFICATION
================================================================================
  System: Single-Owner Warehouse-Centric Event ERP (4 Godowns)
  Target Business: Krishna Tent & Events
  Core Lifecycle: WAREHOUSE -> STOCK -> CRM -> QUOTATION -> BOOKING -> RESERVATION 
                  -> DISPATCH -> SITE SETUP -> RETURN -> VERIFICATION -> AVAILABLE
================================================================================


================================================================================
1. USER ENTRY & FIRST-TIME SETUP WIZARD FLOW
================================================================================

1.1 OPEN ERP SYSTEM
    - System opens at URL: http://localhost:3000/login
    - AuthGuard checks if user is logged in via JWT stored in LocalStorage/Cookies.
    - If unauthenticated, user is presented with the Login Screen.

1.2 OWNER LOGIN
    - Form Fields: Email / Username, Password, Remember Me check
    - API Call: POST /api/auth/login
    - Response: Returns JWT Access Token, Refresh Token, User Profile, Role & Permissions.

1.3 FIRST-TIME SETUP WIZARD (If Company is not configured)
    - If System detects company details are missing, redirects to `/setup-wizard`.
    - Step 1: Company Profile (Name, Owner Name, Phone, Email, Address, GSTIN, Logo upload)
    - Step 2: 4 Godowns Setup (Main Warehouse, Godown 2, Godown 3, Godown 4 names & locations)
    - Step 3: Default Categories (Furniture, Lighting, Tents/Decor, Sound/AV, Power/AC)
    - Step 4: Admin & Staff Accounts Creation
    - API Call: POST /api/settings/setup-wizard
    - Redirect: User redirected to Owner Dashboard (`/dashboard`).


================================================================================
2. CUSTOMER & LEAD MANAGEMENT WORKFLOW
================================================================================

2.1 LEAD CAPTURE & PIPELINE
    - Flow: New Customer Enquiry (Phone/Walk-in) -> Lead Form Entry -> Pipeline Stage
    - Lead Stages: New -> Contacted -> Site Visit Scheduled -> Requirement Discussed -> Quotation Sent -> Booked -> Lost
    - API Endpoints:
      * GET    /api/crm/leads        (Fetch all leads with search/filter)
      * POST   /api/crm/leads        (Create new lead)
      * GET    /api/crm/leads/:id    (Get lead details)
      * PUT    /api/crm/leads/:id    (Update lead info/status)
      * DELETE /api/crm/leads/:id    (Delete lead)

2.2 CUSTOMER MANAGEMENT (SINGLE VS CORPORATE / AGENCY)
    - Once Lead is qualified or booking is initiated, Lead converts to Customer DB.
    - Single / Retail Customer: One-off individual booking (Wedding, Birthday). Standard retail price list, standalone booking ledger.
    - Corporate / Agency / Hotel Customer: Running multiple simultaneous bookings (e.g. 5-10 events/month). Features Parent Account, Credit Limit (e.g. Rs. 10,00,000), Credit Term (e.g. 30 Days Net), Contract B2B Discount Tier, Bulk Payment Allocation across multiple invoices, and Credit Limit Breach Alerts.
    - Form Fields: Customer Name, Customer Type (Retail Individual / Corporate Agency / Hotel / Resort), Phone, Email, Alternate Contact, Billing Address, GST Number, Credit Limit Amount, Payment Term Days, Contract Discount %, Notes
    - API Endpoints:
      * GET    /api/crm/customers                  (List paginated customers)
      * POST   /api/crm/customers                  (Create customer profile)
      * GET    /api/crm/customers/:id              (Customer detail & multi-event history)
      * PUT    /api/crm/customers/:id              (Edit customer details & credit terms)
      * DELETE /api/crm/customers/:id              (Soft delete customer)
      * GET    /api/crm/customers/:id/statement    (Consolidated Statement of Account across all bookings)
      * POST   /api/payments/bulk-allocation       (Bulk payment distribution across multiple event invoices)

2.3 SITE VISIT WORKFLOW
    - Flow: Schedule Visit -> Assign Supervisor -> Visit Site -> Take Dimensions/Photos -> Record Requirements
    - Form Fields: Customer ID, Event Venue Address, Visit Date & Time, Assigned Supervisor ID, Site Dimensions (Length, Width, Height), Power Supply Available (Yes/No), Vehicle Access (Easy/Difficult), Special Remarks
    - API Endpoints:
      * GET    /api/crm/site-visits        (List site visits)
      * POST   /api/crm/site-visits        (Schedule site visit)
      * GET    /api/crm/site-visits/:id    (Get visit details)
      * PUT    /api/crm/site-visits/:id    (Update visit/upload site notes)
      * DELETE /api/crm/site-visits/:id    (Cancel visit)


================================================================================
3. COMPLETE PAYMENT & FINANCE WORKFLOW
================================================================================

3.1 ADVANCE PAYMENT (At Booking Confirmation)
    - Customer pays advance (e.g. 30% - 50% of quotation total).
    - Payment Form Fields: Booking ID, Customer ID, Payment Date, Amount, Payment Method (Cash/UPI/Bank Transfer/Cheque), Transaction Ref No, Payment Type (Advance), Remarks
    - Automation: Generates Payment Receipt, auto-posts entry to Cashbook/Bankbook.
    - API Endpoints:
      * GET    /api/payments          (List payments)
      * POST   /api/payments          (Record payment)
      * GET    /api/payments/:id      (Payment detail & receipt PDF)
      * PUT    /api/payments/:id      (Update payment record)
      * DELETE /api/payments/:id      (Void payment)

3.2 EVENT EXPENSE TRACKING
    - Supervisors/Managers log operational expenses incurred during event setup/dispatch.
    - Form Fields: Event ID, Expense Category (Labour, Transport/Fuel, Food/Catering, Miscellaneous, Equipment Repair), Amount, Paid To, Payment Mode, Voucher Photo Upload, Notes
    - API Endpoints:
      * GET    /api/expenses          (List expenses)
      * POST   /api/expenses          (Log expense)
      * GET    /api/expenses/:id      (Expense detail)
      * PUT    /api/expenses/:id      (Edit expense)
      * DELETE /api/expenses/:id      (Delete expense)

3.3 VENDOR PAYMENTS
    - Payments made to third-party vendors for hired equipment or outsourced staff.
    - API Endpoints:
      * GET    /api/vendors/:id/payments  (List vendor payment ledger)
      * POST   /api/payments/vendor       (Make vendor payment)

3.4 FINAL PAYMENT & GST INVOICE GENERATION
    - After event completion and verification, final balance payment is collected.
    - Invoice Form Fields: Booking ID, Invoice Date, Due Date, Tax Rates (CGST 9%, SGST 9% or IGST 18%), Discount Amount, Payment Terms, Extra Charges (Damage charges, overtime)
    - PDF Generation: Downloadable GST Tax Invoice with QR code & bank payment details.
    - API Endpoints:
      * GET    /api/invoices           (List invoices)
      * POST   /api/invoices/generate  (Generate tax invoice)
      * GET    /api/invoices/:id       (Get invoice detail & PDF)
      * PUT    /api/invoices/:id       (Update invoice status: Paid/Unpaid)
      * DELETE /api/invoices/:id       (Cancel invoice)

3.5 CASHBOOK & BANKBOOK LEDGERS
    - Cashbook: All physical cash incoming (advance/final) and cash outgoing (labour/fuel).
    - Bankbook: Online UPI, NEFT, Cheque credits & debits.
    - API Endpoints:
      * GET    /api/finance/cashbook   (Fetch daily cashbook entries & closing balance)
      * GET    /api/finance/bankbook   (Fetch daily bankbook entries & reconciliation)
      * GET    /api/finance/pnl        (Event-wise P&L and overall profit report)


================================================================================
4. END-TO-END EVENT LIFECYCLE WORKFLOW
================================================================================

STAGE 1: QUOTATION BUILDER & STOCK CHECK
  - User selects items, quantities, rental duration (start date & end date).
  - System performs real-time availability check across ALL 4 GODOWNS.
  - Generates Quotation PDF with itemized costs & terms.
  - API Endpoints:
    * GET    /api/quotations                 (List quotations)
    * POST   /api/quotations                 (Create quotation)
    * POST   /api/quotations/check-stock     (Check live stock across 4 godowns)
    * GET    /api/quotations/:id             (Get quotation detail & PDF)
    * PUT    /api/quotations/:id             (Edit quotation)
    * DELETE /api/quotations/:id             (Delete quotation)

STAGE 2: BOOKING CONFIRMATION & ADVANCE
  - Customer approves quotation -> Quotation converts to Booking.
  - Booking status moves to `CONFIRMED` upon advance payment recording.
  - Rental agreement contract generated.
  - API Endpoints:
    * GET    /api/bookings                   (List bookings)
    * POST   /api/bookings                   (Create booking from quotation)
    * GET    /api/bookings/:id               (Get booking details)
    * PUT    /api/bookings/:id               (Update booking details)
    * DELETE /api/bookings/:id               (Cancel booking & release reservation)

STAGE 3: MULTI-GODOWN MATERIAL RESERVATION & SPLIT
  - System locks required quantities for the event dates.
  - Auto-split algorithm suggests optimal allocation from Godown 1, 2, 3, 4.
  - Item status changes from `Available` to `Reserved`.
  - API Endpoints:
    * GET    /api/reservations               (List reservations)
    * POST   /api/reservations               (Create reservation)
    * POST   /api/reservations/suggest-split (Algorithm recommendation across godowns)
    * POST   /api/reservations/:id/lock      (Lock stock)
    * POST   /api/reservations/:id/release   (Release stock)

STAGE 4: LOADING SLIP & VEHICLE DISPATCH
  - Store Manager generates Godown Loading Slips for each godown.
  - Manual loading verification checklist used during loading into assigned vehicle.
  - Dispatch status changes to `DISPATCHED`. Material status -> `In-Transit`.
  - API Endpoints:
    * GET    /api/dispatches                 (List dispatches)
    * POST   /api/dispatches                 (Create dispatch order)
    * GET    /api/dispatches/:id/loading-slip (Get godown loading slip)
    * PUT    /api/dispatches/:id/status      (Update status: Loading -> Dispatched)
    * DELETE /api/dispatches/:id             (Cancel dispatch)

STAGE 5: SITE RECEIPT, SETUP & EVENT EXECUTION
  - Supervisor receives vehicle at site, verifies material against Loading Slip.
  - Setup completed -> Supervisor uploads setup photos & marks attendance.
  - Material status -> `At Site`.
  - API Endpoints:
    * GET    /api/events                     (List active events)
    * POST   /api/events/:id/site-receipt    (Confirm site receipt & photo upload)
    * PUT    /api/events/:id/status          (Update status: Setup -> Live -> Complete)

STAGE 6: PACKING, RETURN & GODOWN RECEIVING
  - Event concludes -> Packing checklist verified by supervisor.
  - Loaded back into vehicle -> Dispatched to godowns.
  - Store Manager receives vehicle at godown door.
  - API Endpoints:
    * GET    /api/returns                    (List return dispatches)
    * POST   /api/returns                    (Create return slip)
    * PUT    /api/returns/:id/receive        (Confirm godown receipt)

STAGE 7: GODOWN VERIFICATION & ITEM CLASSIFICATION
  - Returned items inspected and classified into 5 categories:
    1. GOOD      -> Returns immediately to `Available` stock.
    2. DAMAGED   -> Moves to `Repair` section; damage charges billed to customer.
    3. REPAIR    -> Sent to repair vendor via repair request.
    4. MISSING   -> Billed to customer; inventory count updated.
    5. SCRAP     -> Unrepairable; written off & sold as scrap.
  - API Endpoints:
    * GET    /api/verifications              (List verifications)
    * POST   /api/verifications              (Submit godown verification)
    * POST   /api/repairs                    (Create repair request)
    * POST   /api/scraps                     (Create scrap request)
